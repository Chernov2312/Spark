# Frontend Spark — документация

Одностраничное приложение мессенджера **Spark** на React + Vite. Тёмная тема, роутинг, работа с REST API и WebSocket.

Форма входа принимает электронную почту и пароль. Адрес передаётся в OAuth2-поле `username`; тег используется для поиска пользователей, а не для входа.

В списке чатов показываются последнее сообщение и его время, включая сообщения из очереди. Для сообщений без текста отображается тип вложения или имя файла; ответы отмечены «В треде». Превью сохраняется после перезагрузки и обновляется при изменении или удалении сообщения.

Иконка и название в шапке открывают информацию о чате; кнопка «Вернуться к сообщениям» возвращает переписку. В профиле можно загрузить личную картинку (JPEG, PNG, WebP, GIF, до 5 МБ) или вернуть общую. Выбор сохраняется в БД отдельно для каждого участника и виден только ему, включая список чатов. Кнопка «Добавить общее фото чата» доступна только владельцу и модераторам; обычные участники могут менять свою личную картинку. Запрет на изменение общего фото также проверяется сервером при выдаче ссылки и сохранении вложения.

Блок «Аватарки группы» в информации о чате показывает все общие фотографии, начиная с текущей. Миниатюра или кнопка «Смотреть все» открывает крупный просмотр со счётчиком и переключением кнопками или стрелками клавиатуры. Escape, кнопка закрытия или нажатие на фон закрывают просмотр; фокус возвращается к исходной кнопке. Просмотр доступен каждому участнику, личная картинка пользователя в общую галерею не включается.

При создании группы выбранные фотографии показываются миниатюрами с удалением; круглое превью показывает последнюю выбранную картинку — будущий аватар чата.

Список участников доступен только в информации о чате. В нём отображаются аватары, имена и роли «Владелец», «Модератор», «Участник». Нажатие на участника открывает карточку профиля с именем, тегом, ролью, датой регистрации и фотографиями. Email и другие приватные данные не отображаются. Карточка закрывается кнопкой, нажатием на фон или Escape, и фокус возвращается к участнику.

В информации о чате кнопка «Настройки чата» открывает выпадающую панель с разделами «Оформление», «Уведомления» и «Приватность». Цвета выбираются компактными образцами, параметры — переключателями. Панель закрывается по Escape, повторному нажатию на кнопку или нажатию вне неё, помещается в экран и прокручивается при нехватке места. Изменения сохраняются автоматически для текущего чата на устройстве. Кнопка браузерных уведомлений показывает состояние разрешения.

Кнопка «Включить фоновые уведомления» регистрирует браузер через Push API. Service Worker `/push-sw.js` показывает уведомление о новом сообщении при закрытой вкладке, а нажатие открывает нужный чат. Текст переписки в фоновой карточке скрыт. Переключатели «Без уведомлений» и «Звук» применяются и к фоновой подписке этого браузера. Выход из аккаунта отзывает подписку устройства.

Кнопка «Начать звонок» открывает панель аудио- и видеозвонков. Участники чата, подключённые к Spark, могут ответить на входящий вызов. Владелец и модераторы могут создать и отозвать гостевые ссылки. Нажатие на созданную ссылку копирует её в буфер обмена. Гость принимает звонок на странице `/call/join`. Сигналы передаются по WebSocket Go-сервиса, гостевые ссылки управляются через его REST API.

Перед входом по приглашению гость может указать ник, который увидят участники. Если оставить поле пустым, Spark назначит имя «Гость N».

В аудио- и видеозвонках участники и гости могут отдельно включать камеру и показывать экран. При показе экрана браузер предлагает выбрать область захвата. Участники видят камеру и экран в отдельных плитках, а звук продолжает идти с микрофона.

Правый клик, долгое нажатие или Shift+F10 на сообщении открывают меню с реакциями, ответом, тредом, пересылкой и закреплением. Для своих сообщений меню также предлагает изменение и удаление. Меню закрывается по Escape или нажатию вне него. Горизонтальный свайп по сообщению открывает ответ с цитатой, вертикальный жест прокручивает переписку.

Над полем ввода при ответе появляются имя автора и фрагмент исходного сообщения. Нажатие на цитату прокручивает переписку к сообщению, крестик справа отменяет ответ и сохраняет черновик.

В тексте сообщений выделяются адреса HTTP(S) и `www.`, электронная почта и телефоны. Нажатие открывает сайт в новой вкладке, почтовое приложение или звонилку. Текст внутри блоков кода и строчного кода сохраняется как код. При отправке, редактировании и пересылке фронтенд выбирает первую поддерживаемую ссылку для карточки и передаёт её в `link_preview_url`. Карточка с доменом, заголовком и описанием обновляется по WebSocket.

При выделении текста в поле сообщения появляется панель с жирным, курсивом, зачёркиванием, моноширинным текстом, цитатой и спойлером. В черновике видна разметка, а в отправленном сообщении — оформление. Спойлер раскрывается нажатием. В кратких превью вместо его содержимого отображается метка «[Спойлер]», а ссылки внутри спойлера не создают карточек.

У вложений `.md` и `.markdown` есть предпросмотр с таблицами, вложенными списками, чек-листами, цитатами и блоками кода. Если история содержит только метаданные, содержимое загружается при открытии предпросмотра. Относительные ссылки и изображения сохраняют подпись.

Закреплённые сообщения отображаются отдельной полосой над перепиской. Кнопка со счётчиком раскрывает полный список с возможностью открепить сообщение. Нажатие на превью показывает исходное сообщение; для ответа в треде открывается соответствующий тред. Список загружается через `GET /chats/{chat_id}/messages/pinned`, независимо от последних 50 сообщений и поисковых фильтров. Закрепление, открепление, редактирование и удаление обновляются через WebSocket; после переподключения список загружается заново.

Кнопка с диаграммой рядом с вложениями открывает создание опроса или викторины. Вопрос содержит до 300 символов, вариантов — от 2 до 10, выбор одного ответа. Независимые переключатели задают анонимность и возможность отменить или изменить голос. В открытом режиме под вариантами видны имена и теги проголосовавших; в анонимном режиме эти данные не выдаются даже автору. В викторине автор отмечает один правильный вариант. Участнику он показывается после голосования: верный вариант зелёный, ошибочный выбранный — красный, результат также подписан текстом. Если отмена разрешена, можно ответить заново; если запрещена, первый ответ окончательный, что проверяется сервером.

Опросы показываются внутри сообщений, сохраняются после перезагрузки, поддерживают треды, ответы и закрепление. Пункт «Отменить голос» находится в меню действий с сообщением (правый клик по опросу или кнопка «⋯») и появляется только после голосования, если разрешена отмена. Событие `poll:updated` обновляет результаты, не передавая в общий WebSocket имена голосовавших или правильный ответ; карточка запрашивает персональные данные через API. Опубликованные опросы нельзя редактировать или пересылать; автор может удалить сообщение целиком.

Через это меню также можно переслать текст и вложения в доступный чат. Горизонтальный свайп по сообщению на сенсорном экране включает ответ с цитатой; вертикальный жест прокручивает историю. В отправленном ответе цитата выделена боковой полосой, показывает короткий фрагмент и имя автора загруженного сообщения. Нажатие на цитату прокручивает историю к загруженному оригиналу. Переключатель в левой панели выбирает все чаты или треды текущего чата. Выбранный тред открывается в основной области переписки; кнопка «Вернуться в чат» возвращает общую историю. На узком экране панель открывается кнопкой «☰». История прокручивается внутри окна; чтение старых сообщений отключает автоматическую прокрутку к новым.

Кнопка «Поиск» рядом с ИИ открывает строку поиска; тип вложения, автор и даты скрыты в выпадающем списке «Фильтры». Для отложенной отправки удерживайте кнопку отправки 600 мс, выберите время и нажмите «Запланировать». С клавиатуры выбор времени открывается стрелкой вниз на кнопке отправки. Расписание хранится в браузере и выполняется, пока приложение открыто.

---

Пересланные сообщения отмечены стрелкой и подписью «Пересланное сообщение», а в списке чатов — префиксом «Переслано». Если чат создал другой пользователь и его нет среди подтверждённых друзей, над перепиской появляется соответствующая отметка.

## 5. API

### `src/api/client.js`

```js
export const api = axios.create({
  baseURL: import.meta.env.VITE_API_URL,
  headers: { "Content-Type": "application/json" },
});
```

**Интерцепторы:**

1. Запрос → `Authorization: Bearer <access_token>`.
2. При `401` защищённого запроса клиент обновляет access-токен через `POST /auth/refresh` и повторяет запрос один раз. Параллельные запросы используют одно обновление. Если refresh-сессия отклонена, клиент очищает локальные данные и открывает `/login`.

**Экспорты:**

```js
setToken(t); // положить access_token
getToken(); // прочитать access_token
clearToken(); // удалить access_token и user
```

### `src/api/auth.js`

| Функция                                       | HTTP                  | Описание                      |
| --------------------------------------------- | --------------------- | ----------------------------- |
| `registerUser({ username, email, password })` | `POST /auth/register` | Запрашивает подтверждение email |
| `loginUser({ username, password })`           | `POST /auth/login`    | Отправляет email как `username` в form-urlencoded |
| `logoutUser()`                                | `POST /auth/logout`   | Отзывает refresh-сессию и очищает localStorage |
| `getCurrentUser()`                            | —                     | Возвращает `user`             |
| `isAuthenticated()`                           | —                     | Есть ли токен                 |

### `src/api/users.js`

| Функция                           | HTTP                           |
| --------------------------------- | ------------------------------ |
| `getMe()`                         | `GET /users/me`                |
| `updateMe({ username?, email? })` | `PATCH /users/me`              |
| `uploadAvatar(file)`              | `POST /users/me/avatar`        |
| `deleteAvatar(url)`               | `POST /users/me/delete/avatar` |

### `src/api/index.js`

```js
export { api, setToken, getToken, clearToken } from "./client";
export * as auth from "./auth";
export * as users from "./users";
```

Использование:

```jsx
import { auth, users } from "../api";

await auth.loginUser({ username: email, password });
const me = await users.getMe();
```

## 6. Аутентификация

### Хранение токена

- `localStorage.access_token` — JWT, поле `access_token` из ответа бэкенда.
- `localStorage.user` — JSON `{ id, username, tag, email }`.
- Refresh-токен браузер хранит в HttpOnly cookie и отправляет с credentialed-запросами авторизации. При подключении и переподключении WebSocket клиент обновляет access-токен, если срок действия истёк или истекает.

### JWT

Payload:

```json
{ "sub": "<UUID пользователя>", "jti": "<ID токена>", "exp": 1734000000 }
```

### Поток «регистрация → чаты»

1. Заполняется `RegisterForm`.
2. Валидация паролей и галочки.
3. `auth.registerUser({ username, email, password })`.
4. Ответ регистрации содержит `verification_required`. Пользователь открывает ссылку из письма.
5. Подтверждение возвращает access-токен и устанавливает refresh cookie. Клиент сохраняет данные пользователя и открывает `/chats`.

### Поток «логин → чаты»

1. `LoginForm` → `POST /auth/login` (form-urlencoded).
2. `200` — токен в localStorage, редирект на `/chats`.
3. `401` — «Неверный email или пароль».

### Logout

```jsx
await auth.logoutUser();
setUser(null);
navigate("/login");
```

## 8. Страницы

### `HomePage.jsx` — `/`

Hero, две кнопки, три карточки фич.

### `RegisterPage.jsx` — `/register`

Обёртка `RegisterForm`, `onSuccess` → `/chats`.

### `LoginPage.jsx` — `/login`

Обёртка `LoginForm` + ссылка на `/register`.

### `ProfilePage.jsx` — `/profile` и `/profile-preview`

VK-стиль: обложка, круглый аватар, имя, табы.

| Проп   | Тип     | Описание                      |
| ------ | ------- | ----------------------------- |
| `demo` | boolean | Данные из `DEMO_USER` без API |

**Функции:**

- Загрузка профиля (`GET /users/me`).
- Смена аватара (`POST /users/me/avatar`).
- Удаление аватара (`POST /users/me/delete/avatar`).
- Редактирование (`PATCH /users/me`).
- Табы: Информация / Друзья / Фото.

### `ChatsPage.jsx` — `/chats`

Слева список чатов, справа переписка. Сейчас на встроенных `MOCK_CHATS` / `MOCK_MESSAGES`.

Когда бэкенд готов — заменить на:

- `chats.listChats()` → `GET /chats`
- `messages.listMessages(chatId)` → `GET /chats/{id}/messages`
- `messages.sendMessage(chatId, text)` → `POST /chats/{id}/messages`

### `FaqPage.jsx` — `/faq`

Аккордеон из 10 вопросов. Плавная анимация раскрытия через `grid-template-rows: 0fr → 1fr`.

Ответы — простые строки в массиве `FAQ_ITEMS`.

## 11. Демо-режим

Два публичных маршрута для работы без бэкенда:

| Маршрут             | Что показывает               |
| ------------------- | ---------------------------- |
| `/register-preview` | Форма регистрации в имитации |
| `/profile-preview`  | Профиль с `DEMO_USER`        |

Компоненты принимают проп `demo`:

- `demo={false}` — реальные запросы.
- `demo={true}` — локальные данные.

**Зачем:**

- Разработка UI без бэкенда.
- Демонстрация интерфейса.
- Обход CORS-проблем.

**Ограничения:**

- Данные не сохраняются на сервере.
- Токен фиктивный.
- Аватар живёт до перезагрузки.

## 12. Типичные ошибки

| Ошибка                     | Причина                                 | Решение                                     |
| -------------------------- | --------------------------------------- | ------------------------------------------- |
| `Failed to resolve import` | Опечатка / файла нет                    | Проверить `dir src\...`                     |
| `X is not defined`         | Забыл импорт                            | Добавить `import X`                         |
| `Invalid hook call`        | Разные версии React и роутера           | `npm install react-router-dom@latest`       |
| `CORS policy`              | Бэкенд не разрешил origin               | `CORSMiddleware` с `http://localhost:5174`  |
| `ERR_CONNECTION_REFUSED`   | Бэкенд не запущен                       | `uvicorn app.main:app --reload --port 8080` |
| Стили не применяются       | `index.css` не импортирован             | Проверить `main.jsx`                        |
| `VITE_API_URL` undefined   | `.env` не в корне / Vite не перезапущен | `.env` → `frontend/`, перезапуск            |
| 401 на приватном роуте     | Токен протух                            | Залогиниться заново                         |
| 422 на регистрации         | Поля не совпадают со схемой             | Сверить с `API.md`                          |

## 13. Сборка и деплой

### Production build

```bash
cd frontend
npm run build
```

Результат — `frontend/dist/`.

### Локальный просмотр

```bash
npm run preview
```

http://localhost:4173

### Деплой

В профиле `prod` Docker Compose собирает `dist/` и копирует его в образ frontend с Nginx. Конфигурация `frontend/nginx.conf` отдаёт статику с fallback на `index.html` для маршрутов React. Профиль `dev` использует Vite и при старте ставит зависимости из `package-lock.json`.

**Для SPA-роутинга** нужен fallback на `index.html`:

**Nginx:**

```nginx
location / { try_files $uri $uri/ /index.html; }
```

**Netlify** — `_redirects`:

```
/* /index.html 200
```

**Vercel** — `vercel.json`:

```json
{ "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }] }
```

### Production `.env`

Для Docker Compose используйте в корневом `.env`:

```dotenv
API_BASE_URL=/api/v1
VITE_CALLS_WS_URL=/v1/calls/ws
```

Compose передаёт адреса в сборку как `VITE_API_URL` и `VITE_CALLS_WS_URL`. При ручной сборке из `frontend/` задайте эти переменные напрямую. После изменения адресов пересоберите бандл.
