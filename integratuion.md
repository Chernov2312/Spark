# Минимальные интеграции для корпоративного мессенджера Spark

Минимум для пилота внутри одной компании — корпоративный вход, управление доступом сотрудников, хранение и восстановление переписки и файлов, централизованный аудит и оповещения дежурной команды. Для хранения и фоновых задач Spark уже использует PostgreSQL, Redis, Celery и S3-совместимое хранилище. Корпоративный вход, синхронизация каталога и аудит действий описаны ниже как задачи внедрения. [Архитектура и запуск Spark](Readme.md)

## 1. Корпоративный вход

Подключить один корпоративный провайдер удостоверений (IdP) по OpenID Connect. Вход проходит через Authorization Code с PKCE, а провайдер применяет политику многофакторной аутентификации компании. Spark связывает внешний аккаунт с внутренним пользователем по паре `iss` и `sub`. Рабочая почта используется для профиля и может меняться. Право входа выдаётся назначением приложения или через выделенную группу в IdP. Сейчас Spark поддерживает вход по email и паролю с выдачей JWT. [Текущий API Spark](api.md) · [OpenID Connect Core](https://openid.net/specs/openid-connect-core-1_0.html) · [RFC 9700](https://www.rfc-editor.org/rfc/rfc9700.html)

## 2. Каталог сотрудников и отзыв доступа

Подключить тот же IdP или корпоративный каталог через SCIM 2.0. Для пилота достаточно получать стабильный идентификатор сотрудника, имя, рабочую почту и статус аккаунта. Идентификаторы каталога и SSO связываются по явному сопоставлению, заданному провайдером. Повторная синхронизация обновляет существующую запись. При деактивации Spark отзывает свои сессии, закрывает открытые WebSocket-соединения и прекращает выдачу новых ссылок на вложения. Уже выданные ссылки могут действовать до окончания срока подписи, поэтому срок выбирают с учётом требований компании к отзыву доступа. [RFC 7644](https://www.rfc-editor.org/rfc/rfc7644.html) · [Временные ссылки в API Spark](api.md)

## 3. Хранение данных и резервное копирование

Подключить PostgreSQL для пользователей и истории, Redis и Celery для доставки событий и фоновых задач и приватный S3-бакет для вложений. Для очереди сообщений в Redis настроить сохранение данных при перезапуске и отслеживать задержку записи в PostgreSQL. Подключить PostgreSQL и бакет к корпоративному резервному копированию. Согласовать допустимую потерю данных и время восстановления, затем проверить восстановление чата вместе с его файлами на тестовом стенде. [Инфраструктура Spark](Readme.md) · [Загрузка и выдача вложений](api.md)

## 4. Централизованный аудит и мониторинг

Передавать в корпоративную систему журналов события входа, изменения ролей и состава чатов, блокировки аккаунтов и административного доступа к данным. Для события сохранять время, тип операции, идентификаторы инициатора и объекта и результат. Ограничить доступ к журналу и задать срок хранения по правилам компании. В мониторинге достаточно оповещений о недоступности API, ошибках WebSocket, накоплении очереди и сбоях резервного копирования. [NIST SP 800-53 Rev. 5, раздел AU](https://csrc.nist.gov/pubs/sp/800/53/r5/upd1/final)

## Почта

Если на пилоте используются локальные аккаунты Spark, подключить корпоративный SMTP-релей для подтверждения адреса и восстановления пароля. Для доставки служебных писем уже используются фоновые задачи Celery. [Настройка почты Spark](Readme.md#настройка-почты)

## Проверка перед пилотом

- Сотрудник с назначенным доступом входит через IdP, а изменение рабочей почты сохраняет его историю.
- После деактивации сотрудник теряет доступ к API, открытому WebSocket и получению новых ссылок на файлы в согласованный срок.
- Резервная копия восстанавливает сообщения и связанные вложения. Сбой фоновой записи вызывает оповещение.
- В корпоративном журнале по идентификатору сотрудника находятся вход, изменение роли и отзыв доступа.
