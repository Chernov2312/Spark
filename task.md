# API групп, поиска пользователей и нескольких аватарок

Фронтенд использует описанные ниже API для создания групп, поиска пользователей по username, выбора участников, загрузки нескольких аватарок и отображения `avatar_urls`.

## 1. Поиск пользователей по username

Аутентифицированный endpoint:

```http
GET /api/v1/users/search?username=<prefix>&limit=20
Authorization: Bearer <token>
```

Ожидаемый ответ:

```json
{
  "users": [
    {
      "id": "11111111-eeee-aaaa-bbbb-cccccccccccc",
      "username": "john_doe",
      "avatar_urls": ["https://storage.example/presigned-get-url"]
    }
  ]
}
```

Контракт:
- Искать по префиксу username без учета регистра; исключить текущего пользователя.
- Валидировать минимальную длину поисковой строки и ограничить `limit` (например, максимум 20).
- Не возвращать email, пароли, токены и другие приватные поля.
- Возвращать UUID для передачи в существующий `POST /api/v1/chats/{chat_id}/users` (`{"user_ids": ["..."]}`).
- Использовать стабильную сортировку и корректно обрабатывать отсутствие результатов.

## 2. Создание группы

`POST /api/v1/chats`:
- Поле `id` должно быть необязательным либо nullable с default `null`.
- Создание без `invited_user_ids` должно быть допустимо; владелец добавляется в участники один раз.
- `avatar_urls` не должно приниматься как произвольные URL для сохранения аватара. Аватары создаются через вложения, описанные ниже.
- Возвращать `avatar_urls` с корректным именем поля (без опечатки `avater_urls`).
- Фиксировать транзакцию после создания чата и связей участников.

Добавление найденных пользователей может продолжить использовать существующий маршрут:

```http
POST /api/v1/chats/{chat_id}/users
Content-Type: application/json

{"user_ids": ["11111111-eeee-aaaa-bbbb-cccccccccccc"]}
```

## 3. Загрузка нескольких аватарок группы

Общий media flow для `type: "chat_avatar"`:

```http
POST /api/v1/attachments/temporary-url
Content-Type: application/json

{
  "file_extension": "webp",
  "file_content": "image/webp",
  "target_id": "<chat_id>",
  "type": "chat_avatar"
}
```

Схема `AvatarUrlRequest` требует `target_id: str`. Значение идентифицирует целевую группу для `chat_avatar` и целевого пользователя для `message` и `user_avatar`. Ответ содержит `chat_id` или `user_id` соответственно, а также `temporary_url` и `file_key`.

После успешного PUT файла зарегистрировать отдельное вложение для каждого изображения:

```http
POST /api/v1/attachments/
Content-Type: application/json

{
  "chat_id": "<chat_id>",
  "is_avatar": true,
  "file_key": "chat_avatar/<chat_id>/<generated-name>.webp",
  "file_name": "group-avatar.webp",
  "file_size": 2048,
  "mime_type": "image/webp",
  "text": null
}
```

Требования к регистрации:
- Читать значения из переданного объекта схемы, не из атрибутов класса.
- Использовать имена схемы `file_name`, `file_size`, `mime_type`.
- Для `is_avatar: true` сохранять `chat_id`, чтобы запись попадала в связь `Chat.avatars`; не привязывать её как пользовательский файл.
- Возвращать `AttachmentResponse` с действительной GET-ссылкой и `id` созданной записи.
- Проверять, что текущий пользователь является участником/владельцем чата.

## 4. Список аватарок

- `GET /api/v1/chats` должен возвращать все аватарки каждой группы как массив `avatar_urls`, сохраняя порядок добавления.
- После добавления фронтенд перечитывает список групп, чтобы синхронизировать полный массив ссылок.

## 5. Критерии приемки

- Пользователь ищет участника по username, выбирает результат и добавляет его в группу без ручного ввода UUID.
- Группу можно создать без приглашённых, а выбранные участники связываются с ней.
- Можно загрузить более одного изображения группы; после обновления страницы все аватарки продолжают отображаться.
- В ответах API нет опечаток/несогласованных полей; ошибки валидации и прав доступа возвращаются явно.
